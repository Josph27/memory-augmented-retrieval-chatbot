## 1. Decision brief

The existing suite has meaningful protection worth retaining: real SQLite lifecycle/namespace/history tests, real coordinator/graph/context composition with a recording model, deterministic token/ranking/retrieval tests, explicit fake-vector synchronization/repair tests, SDK serialization with intercepted transport, and native-browser UI/state assertions. Mock use alone does not weaken these contracts; mocks often isolate exactly the external boundary under test.

**No whole test-file removals are justified.** No inspected file is proven to have no unique consumer or assertion. Narrow replacement/reduction candidates are listed below. The revised assessment covers every test-source responsibility group: 49 Python sources received main-auditor setup/assertion slices, 31 additional files received independent setup/assertion review, and JS/manual/runner sources are inventoried. This is **bounded static assessment**, not exhaustive branch review of all 600 declared tests under `tests/`. Large adapter files now have assertions sampled across all functions, with selected full composition readings. See [inventory](test-suite-inventory.md) and [all test symbols](test-suite-symbols.md).

The first next step, if separately authorized, is isolation plus execution of already sensitive tests—not broad test expansion. In particular, the graph recording-model test already checks actual request equals the packet and uses the real builder/span path. AUD-17 is a potential **existing failing protection assertion**, not established absence of an actual-request test.

## 5. Classification and duplication decisions

- **Retain:** outcome tests at different seams above, deterministic metrics/negative controls, provider wire contract, fake-vector synchronization, native browser state/provenance. Where only setup was sampled, no blanket retain/duplicate judgment was made.
- **Strengthen:** isolation, measured product-oracle invariants, forced concurrent overlap, storage-failure flags, actual frontend lifecycle coverage and explicit scope of fixture metrics. These are proposed later tasks, not changes authorized by this document.
- **Replace:** selected behavior-by-substring or hardcoded success observations with behavioral oracles **after** preserving unique assertions. `tests/test_product_navigation_asset.py` also checks asset registration and lexical absence of direct-backend/model-call tokens; those distinct architectural checks must not disappear when DOM-string checks are replaced. Neither lexical absence nor its browser sibling proves no runtime network activity. Browser assertions check DOM visibility/mounting and SQL effects; this is not whole-file equivalence.
- **Removal candidate:** **no whole-file removal substantiated**. The three JS probes are not equivalent: `.js` additionally logs update_message, `_2.js` supplies webapp auth/session fields and connect-error diagnostics, and `.cjs` is the simpler CommonJS-named probe. Root upload probes differ in socket/auth versus browser-session-assisted HTTP diagnostics. No checked documentation/script callers were found beyond audit records, but that is not proof manual users have none. TSA-11 identifies one vacuous preservation assertion; replacement is more useful than claiming all anchor tests redundant.
- **Unresolved:** exact empty-valid-extraction progress and integrated latest-user representation are real contract questions. No file is labelled unresolved merely because its initial draft had only an AST inventory. Remaining uninspected branches in large adapter/helper suites are **coverage limits**, not invented product ambiguity. Fixed 50/43 case-count tests protect artifact inventories; no user instruction requires those counts forever. Change deliberately alongside manifests/case consumers rather than treating counts as immutable product intent.

Shared fake model/indexer classes are not sufficient duplication evidence. `test_long_term_store`, cache tests, vector sync tests and eval metrics cover different representations. Dispatcher scope, Chroma postfilter and Inspector privacy likewise have different invariants. Similar happy paths across these files cannot substitute for one another.
