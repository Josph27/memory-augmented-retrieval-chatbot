# Workflow and entry-point map

Package v1.0 · consolidated 2026-10-27 from both static audit passes. Paths/symbols were reconciled for navigation; this consolidation did not re-audit behavior. See [provenance](reports/provenance.md) and [corrected findings](bug-backlog.md). IDs describe responsibilities, not proposed removals.

**Depth:** “Mapped only” means identified consumer/owner, not semantic review. “Main path inspected” and “Main and relevant failure paths inspected” describe historical static reading, not execution or every possible branch. **Every workflow below requires runtime verification.** Existing tests are protection leads; none was run by this work. Lack of a named test means unrecovered coverage, not proof no test exists.

## 1. Composition and state ownership

`app.py` composes configuration, SQLite, per-model `ChatService` and framework callbacks; `src/api_routes.py::register_api_routes` adds a second HTTP surface. `ChatService.__init__` composes the coordinator, source dispatcher, routing, reranking, context manager and short-term/LangMem memory. `src/core/contracts.py::{MemoryCandidate, ContextPacket, WorkflowTrace}` are shared contracts.

`CoordinatorAgent.run_turn` preserves the typed spine: route → source retrieval → normalized candidates → rank/select/budget → packet → validated prompt → `ChatAgent`/model → persistence/memory. Graph mode also coordinates route/retrieve/gist expansion/rerank/context/evidence validation; its mock-answer node does not establish that app generation is mocked. The production coordinator owns final generation.

SQLite `Database` owns chat/message, structured memory, compatibility cache, gist, document registry/association, operation-result and inspection records. Document Chroma and optional structured-memory vectors are separate persistence backends, not part of a SQLite transaction. `cl.user_session` owns connection/navigation state; per-chat lifecycle guards are process-local. No global transaction spans inference, SQLite, vectors and UI emission.

### Frontend and development surface

`braemon/src/App.jsx::App` defines `/` (Home), `/chat/:chatId?` (Chat), `/chats`, `/documents`, `/memories`, `/diagnostics`; `Layout` supplies navigation. `main.jsx` initializes client providers. `ChainlitChat` owns socket connect/disconnect, session ID and `setIdToResume` synchronization, send/upload, and REST lifecycle buttons. `useChatSession`/`useChatMessages`/`useChatInteract` are framework library contracts, not repository backend handlers.

`public/product-navigation.js::{sendLifecycleAction, applyProductState, applyAnswerInspections, openInspector}` supports the native custom shell and Inspector. React does not consume the same product state/error/inspection events (AUD-18). React effect dependencies and resume guards were inspected statically; chat-switch/reconnect behavior was not demonstrated in a browser.

`braemon/vite.config.js` configures React/Tailwind, `consoleForwardPlugin`, HTTP proxies and WebSocket proxy to port 8000. `braemon/console-forward-plugin.mjs::consoleForwardPlugin` injects a dev console forwarder and registers `/__console_forward`, writing browser logs. This is development diagnostics, not a production chat workflow.

## 4. Optional/fallback selection reconciliation

- `AppConfig.from_env` defaults `ORCHESTRATION_MODE=langgraph_demo`; service `run_turn` defaults native when called without app configuration. `native` uses `RoutingAgent` rule/LLM/hybrid; `langgraph_shadow` compares graph while preserving native output; demo uses graph packet when valid, otherwise native/legacy fallback. `normalize_orchestration_mode` handles unknown selectors. These are not equivalent production entry points.
- `MemoryReranker.rank_with_trace` supports deterministic, LLM, cross-encoder and hybrid modes; optional model/load/validation failures retain deterministic fallback. `ContextManagerAgent.build_context_packet` applies scopes, utility/cost, required evidence and overflow pruning after ranking. A score error alone is not proof of final selection order (AUD-04).
- `context_packet_to_model_messages` validates packet messages; invalid shape/severe comparison can use legacy short-term prompt. This remains an active fallback, not a disposable duplicate (AUD-17).
- `load_provider_settings` resolves environment > local settings > module defaults separately for custom/DeepSeek names. Resume helper chooses saved versus current provider model according to its compatibility logic. Routing/reranking share the service model; LangMem has a separate client factory consuming shared settings. Eval answer-model CLI/environment overrides and separate judge resolution differ; legacy shell gates persist (AUD-13).
- Previous-gist generation/retrieval flags, current-gist generation settings, structured lexical/vector/hybrid retrieval, document/custom versus LangChain chunk settings and graph routing are not uniformly wired across compositions (AUD-11). Treat advertised settings as claims until an isolated composition test proves effect.

## 6. Coverage limits and excluded material

Detailed semantic inspection concentrated on `app.py`, `src/`, React source/native JS and selected tests/evaluation paths above. `scripts/`, remaining evaluation metrics/flags, build tooling and docs were partially inspected; see reconstructed reports. No CI directory was found in the checked `.github` path; this is not proof that no external CI exists.

Excluded contents: `data/`, `logs/`, private `.env`/`local_settings.py`, uploads, runtime `.files`, caches, virtual environments, installed/vendor/frontend build contents, generated reports/datasets containing possible runtime material, Git/stash contents and tool/credential metadata directories. Installed framework source contracts were selectively consulted during audit; no environment initialization was performed. Root provider notes contain historical verification claims, not current audit test results.

Remaining gaps: complete real browser chat switching/edit/cancellation; simultaneous worker/process behavior; crash consistency/SQL-vector repair; all entry-point flag combinations and provider model/judge settings; live embeddings/PDF dependencies and inference; exhaustive fixture assertions; external framework endpoint contracts across versions. This map supports targeted protection design, **not an exhaustive semantic-review claim**.
